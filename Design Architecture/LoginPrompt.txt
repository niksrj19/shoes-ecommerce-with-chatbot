Build a production-ready Login Page and Authentication Architecture in Next.js (App Router, TypeScript, Tailwind CSS) that integrates with an existing Node.js backend running on `http://localhost:3000`.

### Backend Integration Context
- **Backend Base URL**: `http://localhost:3000`
- **OAuth Endpoint**: `http://localhost:3000/auth/google` (Initiates Google OAuth redirect)
- **OAuth Callback / Cookie Setting**: Handled entirely by the backend (the backend receives the Google callback, sets the `accessToken` and `refreshToken` via `Set-Cookie` headers, and redirects back to the frontend).
- **Refresh Endpoint**: `http://localhost:3000/auth/refresh` (Exchanges refresh token for new access token)

---

### Core Requirements

1. **Login Page (`app/login/page.tsx`)**:
   - Clean, modern UI with a single **"Continue with Google"** button.
   - When clicked, redirect the browser directly to `http://localhost:3000/auth/google`.
   - Include loading state feedback while handling the navigation.

2. **Cookie Handling Strategy**:
   - Since the Node.js backend sets the cookies directly upon completing the Google auth flow, ensure credentials (`credentials: 'include'` for `fetch` or `withCredentials: true` for `axios`) are enabled on all API requests so the browser automatically sends and receives these cookies.

3. **API Client & Silent Token Refresh (`lib/apiClient.ts`)**:
   - Build a centralized `fetch` or `axios` wrapper for making authenticated requests to the backend.
   - **Automatic Refresh Interceptor**:
     - Intercept `401 Unauthorized` responses.
     - Automatically trigger a call to the backend refresh endpoint (`/auth/refresh`).
     - On success: Retry the original failed request seamlessly.
     - On failure (expired/invalid refresh token): Redirect the user back to `/login`.

---

### File Output Structure Required
1. `app/login/page.tsx` — Login component UI with the Google redirect trigger.
2. `lib/apiClient.ts` — HTTP client configured with credentials support, authorization headers, and 401 token refresh retry logic.
3. `middleware.ts` — Next.js middleware to guard protected routes by checking the presence of the auth cookie.
